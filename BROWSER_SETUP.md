# Бесплатный локальный сбор

Нужны уже работающий Docker Desktop, Python 3.10+ и доступ в интернет. Регистрация в сервисах прокси и подписки не нужны.

## Первый запуск на Mac

1. Запустите приложение: `docker compose up -d --build` из каталога проекта. На компьютере, где проект подготовлен, контейнеры уже запущены.
2. Дважды щёлкните файл **«Запустить сборщик.command»** в каталоге проекта. При первом запуске он установит Playwright в `.runtime/venv`. При наличии Google Chrome используется он; иначе один раз загрузится бесплатный Chromium. Личные профили Chrome не используются.
3. Дождитесь надписи **«Сборщик готов»** в открывшемся окне терминала.
4. Откройте [таблицу](http://localhost:8088) и нажмите **«Запустить сбор»** слева сверху.
5. В отдельном окне браузера пройдите проверку Авито вручную. Когда появятся объявления, сборщик продолжит работу сам. При повторном появлении проверки её также нужно пройти вручную.

Во время сбора держите открытыми браузер и окно сборщика. Закрыть их можно и посреди сбора: очередь и сохранённые карточки остаются в базе. Чтобы продолжить, снова откройте `.command` и нажмите «Продолжить сбор». «Новый обход с начала» заново открывает карточки для обновления цен.

Программа использует отдельный профиль `.runtime/browser-profile`. Cookies проверки сохраняются между запусками, но Авито может запросить проверку повторно. Этот профиль и зависимости исключены из Git и архива исходников. Учётные данные PostgreSQL остаются в Docker и локальному сборщику не передаются.

## Поведение при проверке

Программа открывает страницу один раз и ждёт появления карточек каталога или параметров объявления. Она не нажимает CAPTCHA и не пытается решить её автоматически. При обычной загрузке интерфейс показывает ожидание данных; сообщение о ручной проверке появляется, если она распознана по заголовку страницы. Каждые несколько секунд сборщик подтверждает серверу, что работает.

Если Авито перезагружает страницу во время чтения, сборщик дожидается нового документа и заново проверяет его адрес и готовность в пределах исходного времени ожидания. Повторно открывать объявление для этого не требуется. Отменённый самим сайтом переход также не останавливает сбор, если нужная страница в итоге открылась. Неожиданные ошибки показывают причину в интерфейсе; подробности сохраняются в `.runtime/collector-errors.log` (до трёх файлов по 2 МБ). В журнал не записываются содержимое страницы, cookies, параметры URL и учётные данные из адресов. Чтобы изменения вступили в силу, перезапустите «Запустить сборщик.command» и нажмите «Продолжить сбор»; новый обход не требуется.

Если показано «Объявление не посмотреть» и «Оно ещё на проверке» либо «Объявление закрыто», сборщик пропускает это объявление сразу, не ожидая цену и характеристики. В очереди сохраняется причина, счётчик «Пропущено» увеличивается; уже сохранённые сведения и цены остаются прежними. Следующее объявление открывается автоматически. В новом полном обходе этот ID может быть проверен снова. Эта страница отличается от CAPTCHA и проверки доступа браузера, для которых по-прежнему требуется ручное действие.

Сообщение «Объявление не посмотреть» / «Оно заблокировано после проверки» означает недоступность самого объявления. Сохранённое объявление переносится в архив с этой причиной, история цен сохраняется, а сбор продолжается без ожидания цены или CAPTCHA. Такой же порядок действует для закрытых, истёкших, отклонённых и удалённых объявлений.

Объявления с заголовком «Аукцион: …» или значением «аукцион» в условиях/способе продажи тоже сразу пропускаются. Ожидать цену и адрес для них не требуется. В очередь записывается причина пропуска, сбор продолжается; стартовая аукционная цена не попадает в историю обычных цен.

После появления заголовка и цены сборщик дополнительно ждёт адрес до 10 секунд: этот блок может загрузиться позднее. Парсер читает видимый адрес (в том числе блок `#item-view-address` при хешированных CSS-классах), микроданные `PostalAddress`, JSON-LD и поле «Адрес» в характеристиках. Один город без улицы или другого уточнения не подставляется вместо адреса квартиры. Если адрес не удалось прочитать, объявление пропускается с явной ошибкой.

Свободная планировка может быть указана в количестве комнат, отдельном поле планировки или заголовке. Для неё число комнат может отсутствовать: в таблице отображается «Свободная планировка», а студии учитываются отдельно. Такие карточки проходят обычную очередь и сохраняют историю цен. Ранее пропущенные с ошибкой карточки повторяются при продолжении обхода.

После обновления файлов сборщика закройте его окно браузера и снова откройте **«Запустить сборщик.command»**, чтобы применился новый код. Если запуск ещё отмечен как активный, дождитесь его освобождения (до 2 минут), затем нажмите кнопку сбора повторно. История цен сохраняется.

По умолчанию на загрузку страницы и ручную проверку отведено 300 секунд. Если не загрузилась обычная карточка, сборщик повторит её один раз, затем запишет ошибку и продолжит очередь. При проверке доступа или сбое каталога нужно продолжить сбор после устранения причины. Уже собранные данные не теряются. Значение можно изменить в `.env` через `BROWSER_WAIT_SECONDS`, диапазон 30–1800 секунд.

Закрытие браузера или остановка терминала прерывает текущий сбор. Если связь оборвалась внезапно, сервер освободит задание через 2 минуты. Два локальных сборщика не могут одновременно обрабатывать одно задание.

## Продолжение и охват

Начиная с этой версии в PostgreSQL сохраняются страницы каталога и отдельная очередь ID объявлений. После остановки браузер получает следующий необработанный ID. Запись объявления, цены и выполнение пункта очереди подтверждаются одной транзакцией. Ошибки сохраняются и повторяются при продолжении. HTTP 404/410 пропускается и переносит сохранённую карточку в архив только при совпадении адреса категории и ID итогового объявления.

При первом продолжении после обновления старой версии каталог просматривается с начала: прежний код точной очереди не сохранял. Уже имеющиеся в базе карточки не открываются. Последующие остановки продолжаются по точной очереди.

Отсутствие кнопки перехода больше не завершает обход автоматически: проверяется следующая страница по номеру. Номер сначала проверяется по текущей странице в пагинации, затем по адресу. При расхождении программа ждёт обновления страницы и один раз повторяет переход. При повторном сбросе номера она перепроверяет предыдущую сохранённую страницу: если там подтверждён конец пагинации, текущий диапазон завершается (либо делится, если достиг 30 страниц), а новые ссылки из перепроверенной страницы добавляются в очередь. Если конец не подтверждён, запуск приостанавливается с сообщением об ожидаемом и фактическом номере, браузер остаётся открытым. Можно сохранить страницу для диагностики или нажать «Продолжить сбор» после восстановления доступа. Подтверждённый конец — пустая выдача, явно отключённый переход либо текущая страница в пагинации без доступных переходов вперёд. Один только повтор выдачи подтверждением конца не считается. Счётчики и страница продолжения отображаются над таблицей. Для нового прохода по известным карточкам с обновлением цен есть отдельная кнопка «Новый обход с начала».

Достижение 30 страниц не завершает обход города. Сборщик переходит к диапазонам цены: сначала 1–19 999 999 ₽ и от 20 000 000 ₽, затем при необходимости делит их дальше. Верхней границы для дорогих квартир нет. В каждом диапазоне свои номера страниц, а ID дедуплицируются на весь обход. После остановки сохраняются и диапазон, и очередь карточек. Завершённый старой версией обход из 30 страниц снова можно продолжить; имеющиеся карточки повторно не открываются. Если Авито сбрасывает ценовой фильтр, запуск останавливается с понятным сообщением. Если выдача с одной точной ценой тоже достигнет ограничения, сбор останется частичным. Подробности — в разделе «Почему 30 страниц не означают весь город» в README.

При обновлении потребуется перезапустить `.command`: старый сборщик не совместим с новым протоколом очереди и получает понятное сообщение при подключении. Миграция базы сохраняет объявления и историю цен.

## Настройки

```dotenv
COLLECTOR_MODE=browser
BROWSER_WAIT_SECONDS=300
AVITO_PROXY_URL=
AVITO_PROXY_REQUIRED=false
```

После изменения `.env` пересоздайте контейнеры: `docker compose up -d --no-build --force-recreate backend frontend`. Кнопка запуска ставит задание в очередь; пока локальный сборщик не открыт, в интерфейсе будет сообщение об ожидании.

Если «Ожидается локальный сборщик» не исчезает, проверьте, что открыт `.command`, терминал пишет «Сборщик готов», а `COLLECTOR_MODE=browser` применён к контейнеру. Если сайт не открывается после ручной проверки, текущая сессия не обеспечивает доступ к Авито; этот вариант не гарантирует устранение сетевых или иных ограничений площадки.

## Запуск вручную

Из каталога проекта, при уже установленных зависимостях:

```sh
PLAYWRIGHT_BROWSERS_PATH="$PWD/.runtime/browsers" PYTHONPATH="$PWD/backend" .runtime/venv/bin/python -m app.local_browser
```

Параметр `--api-url http://127.0.0.1:8088/api` позволяет явно указать порт приложения. По умолчанию порт читается из `WEB_PORT` окружения или `.env`. HTML передаётся только локальному приложению. Парсер и вся логика записи цен выполняются в backend.

## Проверено

Тестовые сценарии проверяют цепочку «локальный сборщик → каталог → объявление → история цен», ручную паузу, сообщения о состоянии, таймаут, остановку, истечение связи, запрет обработки чужого задания и отсутствие токена сборщика в публичных ответах API. Тестовые объявления воспроизводят разные варианты разметки адреса, названия ЖК, цены и характеристик на синтетических данных. Живой доступ к Авито в этой среде не проверен из-за ограничения встроенного браузера.
