# Housing Scraper

Сбор объявлений с Авито и история цен на недвижимость. Python, PostgreSQL и интерфейс на React работают в трёх отдельных Docker-контейнерах.

Код интерфейса находится в `frontend/src/`: `main.jsx` переключает разделы, `database.jsx` отвечает за таблицу и прогресс сбора, `analytics.jsx` и `maps.jsx` — за аналитику и карту. В `backend/app/` браузерный сборщик (`local_browser.py`) получает задания через `browser_api.py`; `crawl.py` ведёт очередь, `parser.py` разбирает объявления, а `repository.py` и `listing_history.py` сохраняют цены и состояние.

## Квартиры и дома

Подвкладки **«Квартиры»** и **«Дома»** доступны в базе, аналитике и карте. У рынков независимые фильтры, настройки столбцов, очереди полного обхода, выборки 1000 и обновления. Список городов показывает наличие базы именно выбранного рынка. История цены по ID Авито и архив работают для обоих рынков.

У домов сохраняются площадь дома (м²), участок (сотки), комнаты, этажность, год постройки, адрес, вид объекта, готовность, категория земель, материал стен, терраса/веранда, санузел, ремонт, электричество, отопление, вода, газ, канализация, интернет/ТВ, парковка, транспорт, инфраструктура, отдых, условия продажи и прочие доступные общие поля. Гектары и м² участка переводятся в сотки. Неуказанные параметры остаются пустыми; отсутствие комнат у дома допустимо. Вид объекта можно распознать по заголовку. Цена за м² рассчитывается по площади **дома**, не участка. В аналитике дополнительно рассчитываются среднее, медиана и мода площади участка.

**Загородный радиус:** `round(clamp(35 × (P / 587225)^(1/3), 15, 70))` км, где P — население из встроенного [справочника HFLabs](https://github.com/hflabs/city), 587225 — значение Иркутска в том же снимке данных. Это настраиваемая эвристика поиска, не административная граница и не оценка транспортного времени. Кубический корень даёт умеренный рост при увеличении города. Иркутск — 35 км, без сведений о населении — 25 км. Население в справочнике может быть устаревшим; автоматическое обновление не выполняется. Можно установить радиус 5–100 км или вернуться к автоматическому значению в разделе «Дома» базы. Изменение действует для новых обходов; начатая очередь фиксирует радиус. Если изменён адрес самого каталога, продолжение старой очереди останавливается с объяснением и не сбрасывает прогресс.

Радиус передаётся в фильтре Авито (формат подтверждён предоставленной пользователем ссылкой вместе с ценой). Он сохраняется при разбиении на ценовые группы, пробах выборки и продолжении. Сброс радиуса сайтом останавливает обход с сохранением очереди. Ссылки на дома соседних населённых пунктов допускаются; перед сохранением координаты объявления проверяются по расстоянию по прямой от центра выбранного города. Дома вне радиуса пропускаются; без координат включение не подтверждается и карточка пропускается с объяснением. Расчётное расстояние и указанное Авито расстояние хранятся отдельно. Пунктирная окружность на карте обозначает радиус сбора.

Параметр API `property_kind` принимает `apartment` (по умолчанию) или `house` в таблице, аналитике, карте, справочниках, прогрессе и запуске. Фильтры домов: `land_area_min/max`, `distance_to_center_km_min/max`, а также повторяемые коды характеристик `object_type`, `readiness`, `land_category`, `wall_material`, `terrace`, `electricity`, `heating`, `water_supply`, `gas`, `sewerage`, `internet_tv`, `communications`, `recreation`, `transport_access`, `infrastructure`, `house_bathroom`. Радиус: `PUT /api/cities/{id}/house-radius` с `{"radius_km":35}`; `null` возвращает автоматическое значение.

Для офлайн-импорта дома доступен `python -m app.collect --property-kind house --city-id ID --html файл.html --url ИСХОДНЫЙ_URL`. Импорт проверяет радиус так же, как браузерная очередь.

После установки обновления перезапустите «Запустить сборщик.command»: дома требуют протокол сборщика 5. Миграция 012 сохраняет принадлежность дома к нескольким городским зонам, не дублируя объявление и цены; исторические снимки сохраняют известные на тот момент зоны. Миграция 011 относит все прежние записи и очереди к квартирам, сохраняя историю и прогресс.

## Запуск

Для запуска нужны Docker с Compose и Python 3.10 или новее для локального сборщика. Клонируйте репозиторий и запустите сервисы:

```sh
git clone https://github.com/Frozet/housing-scraper.git
cd housing-scraper
docker compose up -d --build
```

При первом запуске создаётся пустая база PostgreSQL. Чтобы изменить локальные настройки, скопируйте `.env.example` в `.env` и отредактируйте копию.

На Mac откройте двойным щелчком **«Запустить сборщик.command»** из каталога проекта. Первый запуск установит бесплатную библиотеку Playwright в локальное окружение; если Google Chrome не установлен, будет загружен Chromium. Откроется отдельное окно браузера. Затем откройте <http://localhost:8088> и нажмите слева сверху **«Запустить сбор»**. Если Авито покажет проверку или CAPTCHA, пройдите её вручную в этом окне браузера. Сборщик дождётся открытия страницы и продолжит обход.

Кнопка ставит задание в очередь PostgreSQL. Локальный сборщик получает его и передаёт HTML в backend; сервер извлекает данные и сохраняет цены. После сбора таблица обновляется автоматически. Таблица содержит все запрошенные характеристики, доступные на странице объявления, с пагинацией по 100 строк и горизонтальной прокруткой. Окно браузера и окно сборщика должны оставаться открытыми во время работы.

Для запуска программы не нужны регистрация в сторонних сервисах, платная подписка и покупка прокси. По умолчанию используется локальный браузер через ваше интернет-соединение. Подробности — в [BROWSER_SETUP.md](BROWSER_SETUP.md). Собственный прокси остаётся необязательной настройкой отдельного HTTP-режима по [инструкции](PROXY_SETUP.md).

**Нажмите на цену**, чтобы увидеть историю этого объявления: первоначальную цену, последующие изменения, величину изменения и даты наблюдения. История связывается исключительно по ID объявления Авито. Разные объявления по одному адресу считаются отдельными объявлениями.

## Обновление объявлений и архив

Карточка, которая не загрузилась или открылась по другому адресу, получает две попытки. Затем она отмечается ошибкой, а сбор продолжается. При возобновлении можно повторно прочитать такие карточки. Проверка доступа и неподтверждённый каталог по-прежнему останавливают обход с сохранением прогресса. HTTP 404/410 архивирует объявление только при подтверждении его ID и итогового адреса.


**«Обновить объявления»** создаёт отдельную очередь всех актуальных сохранённых объявлений выбранного города. Фильтры таблицы не ограничивают эту очередь. Каталог и новые объявления не просматриваются. Используется тот же локальный браузерный сборщик; после остановки нажмите «Продолжить сбор». Очереди полного обхода, выборки 1000 и обновления независимы.

При проверке изменённые характеристики заменяются, новые добавляются; необязательное поле, которое страница не передала, не стирает ранее известное значение. Явное «нет» учитывается как изменение. Новая запись цены появляется только при её изменении. Закрытые объявления и подтверждённые HTTP 404/410 переносятся в архив с датой обнаружения и причиной; ошибки разбора, модерация и ограничения доступа архивирование не вызывают. Повторно найденная открытая карточка автоматически возвращается в актуальные. Объявления, параметры и история цен физически не удаляются.

Во всех разделах фильтр **«Актуальность объявлений»** предлагает актуальные объявления (по умолчанию), только архив или все объявления. В таблице доступен столбец «Актуальность». Поле `listing_status` в API принимает `active`, `archived`, `all`. Для запуска обновления передайте `collection_mode:"refresh"` в обычный `POST /api/runs`.

## Аналитика за месяц

В фильтре **«Месяц и год»** выберите год и нажмите нужный месяц, затем **«Применить фильтры»**. Доступны месяцы, для которых есть сохранённое состояние объявлений выбранного города и типа недвижимости. **«Текущие данные»** показывает текущую базу. Историческая выборка использует последние характеристики, архивный статус и цену на конец месяца по времени Иркутска. Для незавершённого месяца учитываются наблюдения к текущему моменту. Все фильтры, включая ЖК и отделку, работают с историческими значениями. Параметр `month` у `/api/analytics` и `/api/listings/filter-options` имеет формат `YYYY-MM`.

Миграция 010 сохраняет исходный снимок существующих объявлений на дату их последней проверки: более ранние характеристики в прежней базе не хранились и не восстанавливаются предположениями. Новые снимки параметров и статуса записываются только при изменениях, в одной транзакции с текущей записью и ценой. Существующая история цен полностью сохраняется.

## Сортировка таблицы

Нажмите на заголовок со стрелками: количество комнат, общая площадь, площадь кухни, жилая площадь, этаж, высота потолков, отделка или цена. Первое нажатие сортирует по возрастанию, повторное — по убыванию; стрелка показывает текущее направление. Сортировка выполняется в PostgreSQL по всей базе до разбиения на страницы. При смене столбца/направления открывается первая страница. Выбор сохраняется при переходе между страницами, автоматическом обновлении и нажатии «Обновить таблицу».

Этаж сравнивается по этажу квартиры, цена — по последнему наблюдению. Студии имеют число комнат 0, свободная планировка без числа комнат относится к пустым значениям. Пустые значения всегда стоят в конце независимо от направления. Отделка сравнивается по алфавиту без учёта регистра; несколько значений отделки предварительно упорядочиваются и сравниваются как одна строка. Совпавшие значения дополнительно упорядочиваются по ID записи для стабильной пагинации. По умолчанию сохраняется порядок по времени последней проверки.

## Фильтры и цена за м²

После цены отображается «Цена за м²»: последняя сохранённая цена делится на общую площадь, результат округляется до двух знаков. Значение вычисляется при чтении из базы, не дублируется отдельным полем. Оно доступно для сортировки и диапазона; фильтр использует то же округлённое значение, которое показывает таблица. При отсутствии цены выводится прочерк.

В блоке над таблицей можно выбрать тип жилья, несколько вариантов числа комнат (включая студии и свободную планировку), диапазон общей площади, этаж квартиры, этажность дома, балкон/лоджию, высоту потолков, варианты санузла, отделку, диапазоны цены и цены за м². Нажмите «Применить фильтры»; «Сбросить все фильтры» также очищает выбор ЖК. Границы диапазонов включительные. Несколько галочек одного поля объединяются по «или», разные фильтры — по «и». Записи с неизвестной характеристикой не соответствуют диапазону этой характеристики. Для балкона варианты «Нет» и «Не указано» различаются: отсутствие поля не принимается за явное отсутствие балкона.

В заголовке «Название ЖК» открывается список всех комплексов, представленных в базе, с поиском и галочками. Выбор нескольких ЖК применяется сразу; «Все ЖК» снимает ограничение. «Без указания ЖК» выбирает записи без названия комплекса. Список остаётся полным при других фильтрах, в том числе при пустом результате. Списки вариантов обновляются после завершения сбора либо кнопкой «Обновить таблицу».

Фильтры и сортировка выполняются до пагинации, применяются ко всей базе и сохраняются при обновлении таблицы и переходах между страницами. Новый выбор открывает первую страницу. Над таблицей видны число подходящих записей и общее число объявлений.

## Аналитика

В интерфейсе три раздела: **«База данных»** сохраняет таблицу, историю цен, сортировку и управление сборщиком; **«Аналитика»** содержит фильтры слева и вычисляемые показатели справа; **«Карта»** показывает расположение и тепловую карту цен. Переключатель квартир и домов расположен справа в общей строке разделов. Выбор фильтров каждой вкладки сохраняется при переключении между ними.

В аналитике действуют общие фильтры города, рынка, актуальности, характеристик, назначения, объекта продажи и стадии строительства. В основной таблице показаны P10, P25, медиана, P75, P90, среднее и наиболее частый диапазон цены, цены за м², площади дома/квартиры и (для домов) участка. Единицы масштабируются в названии строки. Точная мода находится в раскрываемых дополнительных показателях.

P25–P75 охватывает центральную половину, P10–P90 — центральные 80% объявлений. Процентили вычисляются линейной интерполяцией по позиции `(n − 1) × p` и округляются до двух знаков по правилу «половина вверх». Для цены за м² используются те же значения с точностью до копеек, что и в таблице. Это распределение цен предложений загруженной базы, а не цен сделок. Все подходящие объявления учитываются по одному разу, по последней известной цене на выбранную дату. Число проверок и старых цен не повышает вес объявления; отсутствие цены не исключает его из статистики площади.

Гистограмму можно переключать между ценой, ценой за м² и площадями. Ширина интервалов подбирается по межквартильному размаху и размеру выборки, центральный охват — от P1 до P99. Далёкие значения остаются в отдельных открытых крайних интервалах; сумма частот всегда равна числу известных значений. Самый частый интервал, включая все равные максимумы, показывается рядом с процентилями. Пустые и постоянные выборки обрабатываются отдельно.

Бюджет задаётся независимо от фильтра цены, допускает одну или обе включительные границы. Доля равна числу подходящих по бюджету объявлений, делённому на число объявлений с известной ценой внутри текущих фильтров. Бюджет не отсекает точки и не меняет остальные показатели. Пустой бюджет не выдаёт фиктивные 100%.

Таблица сравнения одновременно показывает сегменты по комнатам, районам, ЖК, диапазонам площади, отделке, возрасту и типу здания (материалу стен у домов), первичному/вторичному рынку и категориям предложений. Для каждого сегмента показаны количество, число известных цен, медианы, P25–P75 цены и цены м², доля наблюдений за последние 30 дней и медианная давность наблюдения. Текущая свежесть использует дату последней проверки; историческая — дату последнего сохранённого снимка до конца месяца. Возраст здания вычисляется на выбранную дату. Неизвестные значения образуют отдельные строки. При нескольких вариантах отделки/материала объявление может входить в несколько строк; это явно отмечается. Разница медиан сегментов не является оценкой причинной надбавки за новизну.

### Категории предложений и возможные дубли

Независимые признаки `sale_scope` (целиком/доля/не указано), `premise_kind` (жильё/апартаменты/другое нежилое/не указано) и `construction_status` (готовый/строится/недострой/на заказ/не указано) фильтруются в таблице, аналитике и карте. Поэтому доля в апартаментах сохраняет оба признака. Для старых записей используются заголовок и уже сохранённая готовность; обычный заголовок квартиры/дома без признака доли трактуется как предложение целого объекта. Новые явно указанные параметры имеют приоритет. Готовность дома не выводится только из площади, ремонта или года постройки. Свободное описание не используется для поиска слова «доля», чтобы не путать продажу всего объекта с описанием долей собственников.

Район извлекается из явного параметра или адресной подписи Авито. Неизвестные районы не угадываются по названию улицы. Новые признаки сохраняются в нормализованных справочниках характеристик и исторических версиях; существующие записи обогащаются при следующем обновлении. В основной таблице добавлены настраиваемые столбцы «Предложение» и «Район».

Раскрываемая «Проверка возможных дублей» группирует объявления одного рынка и города по адресу конкретного здания и точной площади (до 0,01 м²). Адрес без номера здания не образует группу. Адресные варианты с подтверждённым ключом здания учитываются вместе. В каждой группе можно сравнить заголовки, комнаты, этажи, ЖК, цены и назначение, затем отметить выбранную пару как один объект, разные объекты или отменить отметку. Результат хранится отдельно и не объединяет объявления, цены или статистику. Совпадение адреса и площади само по себе не доказывает дубль, особенно в новостройках.

Каждая отметка и отмена добавляются отдельным событием. Исторический отчёт берёт последнее решение по паре до конца месяца. Миграция 014 сохраняет прежние отметки с их датами; решения, перезаписанные старой версией, восстановить нельзя. Проверка пары хранит отпечатки существенных характеристик. Изменение цены её не отменяет; изменение адреса/площади/этажа/комнат/категории требует повторной проверки. Устаревшая форма получает HTTP 409. Для исторического месяца доступны просмотр кандидатов и только существовавшие к той дате отметки; новые отметки делаются по текущим данным. Запросы аналитики остаются только для чтения.

Три точечных графика показывают: цену объекта по вертикали и общую площадь по горизонтали; цену объекта по вертикали и цену за м² по горизонтали; цену за м² по вертикали и общую площадь по горизонтали. Они доступны для квартир и домов и используют одну отфильтрованную выборку. Каждая точка соответствует одному объявлению с ценой; все точки, включая выбросы, сохраняются.

По умолчанию масштаб автоматический: при наличии далёких значений основная область оси остаётся линейной, затем шаг значений плавно увеличивается. Деления расположены на одинаковом расстоянии, их значения вычисляются по выборке. Плавная функция сохраняет непрерывность масштаба, наклона и кривизны в месте перехода; степень сжатия учитывает размер хвоста, включая выбросы на несколько порядков. Сжатие включается для выборки от 20 объявлений, если максимум более чем в 2,5 раза превышает границу основной области, подобранную по 95-му процентилю. Единицы осей показывают исходные значения. Переключатель «Масштаб графиков» позволяет вернуть линейный вид всех трёх графиков. Плотность делений зависит от ширины экрана; высота графика ограничена диапазоном 300–440 пикселей. Наведение на точку показывает ID, цену, площадь и цену за м². При отсутствии подходящих данных интерфейс сообщает об этом и не строит график.

## Города и выборка 1000

Город выбирается справа в панели вкладки «База данных». В списке есть поиск по названию и региону; города с сохранёнными объявлениями идут первыми и отмечены значком базы. Одинаковые названия различаются регионом. Выбор города распространяется на таблицу, справочники фильтров, аналитику и последующие запуски. Он сохраняется в браузере. Существующие объявления Иркутска и их история остаются в базе. Фильтры базы скрыты по умолчанию; кнопка «Показать фильтры» открывает их без сброса параметров. В аналитике ЖК выбираются галочками, включая «Без указания ЖК».

Справочник содержит 1117 записей из [HFLabs / DaData](https://github.com/hflabs/city), лицензия данных [CC BY-SA 4.0](https://creativecommons.org/licenses/by-sa/4.0/). Источник и преобразования описаны в `backend/app/data/NOTICE.md`. Это локальный снимок справочника, без автоматического обновления. Адреса разделов сформированы по названиям и не являются проверенным справочником Авито: если у города нестандартный адрес, откройте в списке городов «Адрес каталога Авито», вставьте фактическую ссылку на продажу квартир и сохраните. Новый запуск использует её; старый прогресс остаётся в истории. При активном сборе адрес изменить нельзя. Сборщик не подменяет выбранный город другим при ошибке адреса.

Кнопка **«Собрать 1000»** создаёт новую выборку выбранного города. Сначала локальный браузер читает счётчик каталога, затем несколько каталогов с фильтром «цена до…». По этим счётчикам двоичный поиск находит границы 10%, 20%, …, 90% объявлений по цене. Полные карточки на этапе определения границ не открываются. Это ценовые децили по числу объявлений, а не десять равных интервалов рублей. Метаданные сохраняются в `sample_plans`, `sample_boundaries`, `sample_probes`; после остановки работа продолжается с сохранённого запроса.

Границы приблизительные: поиск использует шаг 10 000 ₽, чтобы не тратить десятки запросов на соседние рубли. Если новый счётчик немного нарушает накопленный порядок, отклонение не больше 0,25% исходного числа объявлений (с округлением вверх, минимум два объявления) приводится к ближайшему согласованному значению. Сильное расхождение не сохраняется: тот же ценовой фильтр открывается повторно с обычной паузой сборщика, максимум три попытки. Число попыток сохраняется в `sample_plans.probe_retries` (миграция 009); корректный ответ сбрасывает его. Изменённый фильтр или другой город по-прежнему не принимаются. Старые незавершённые расчёты можно продолжать без очистки границ и без удаления объявлений.

Далее сборщик последовательно сохраняет по **100 успешно прочитанных уникальных объявлений в каждой группе**, всего не более 1000 за выборку. Снятые объявления, аукционы, модерация и ошибки чтения не занимают квоту. Если цена карточки уже вышла за границы группы, она пропускается. При одинаковых ценах граничные диапазоны пересекаются; один ID не учитывается дважды, невыбранные кандидаты можно использовать в следующей группе. Недостающие квоты не заменяются объявлениями из других групп. Фактическое покрытие и границы групп сохраняются в прогрессе выборки, состав — в её очереди. Если для города есть несколько незавершённых режимов, выберите нужную очередь рядом с кнопкой «Продолжить сбор». Полный обход и выборки имеют независимые очереди, но одновременно работает только один сборщик.

Если местная выдача закончилась и Авито показывает блок «объявления есть в других городах», сборщик завершает текущую группу с фактическим количеством записей и переходит к следующей. Пагинация рекомендаций не продолжает сбор этой группы; объявления из блока рекомендаций не попадают в очередь.

Если объявлений мало, выдача ограничена или часть карточек недоступна, результат может быть меньше 1000: статус сообщает о неполной выборке и показывает фактические квоты. Если счётчик не читается или остаётся сильно несогласованным после перепроверок, сбор останавливается с объяснением и сохраняет прогресс; позже можно нажать «Продолжить сбор». Счётчики и цены во время обхода могут меняться; такая выборка не является гарантированно случайной статистической выборкой. Собранные объявления добавляются и обновляются в общей базе города, прежние записи не удаляются.

После обновления закройте прежний локальный сборщик и снова откройте **«Запустить сборщик.command»**. Актуальный протокол сборщика — 7; он передаёт итоговый адрес при HTTP 404/410 и число попыток чтения карточки. Города и выборка доступны в браузерном режиме; HTTP-режим остаётся для полного обхода Иркутска. Проверки Авито по-прежнему проходит пользователь вручную.

## Карта

Вкладка «Карта» использует выбранный город и те же фильтры, что и база данных, включая ЖК. На общем плане соседние точки объединяются; при приближении появляются цены. Квартиры по одному адресу показываются общей точкой с диапазоном последних сохранённых цен. Нажатие открывает список подходящих объявлений; старые наблюдения цены не увеличивают количество квартир и не участвуют в диапазоне. «Показать все точки» возвращает обзор всей выборки.

Координаты новых объявлений берутся из карты текущего объявления Авито или его структурированных данных. Координаты рекомендаций других квартир исключаются. Координаты хранятся в справочнике адресов, отдельно от квартир и истории цены; повторный сбор без координат не стирает известную точку.

Галочка **«Тепловая карта»** включает плавную цветовую заливку: зелёный — низкая цена квартиры, жёлтый — середина шкалы, красный — высокая. Отображается средняя полная цена квартиры поблизости, в рублях, по последним сохранённым ценам и текущим фильтрам. API передаёт среднюю цену и число объявлений с ценой по каждому адресу; диапазон минимум–максимум не подменяет среднее. Пространственное среднее взвешивается по числу квартир и расстоянию. Плотность объявлений влияет на прозрачность, цвет рассчитывается отдельно как средняя цена. Шкала едина для всей отфильтрованной выборки города и не меняется при перемещении карты; крайние 5% значений средних цен по адресам насыщаются цветами концов шкалы. Для одинаковых цен показывается один нейтральный цвет. Участки вне ограниченной окрестности точек остаются прозрачными. Радиус плавно изменяется с масштабом; ядро затухает до нуля с мягкой границей. На тепловую карту попадают только объявления с координатами и ценой. Нажатие на точки и выбор квартир продолжают работать при включённом слое.

Для старых записей при первом открытии карты города фоновый обработчик один раз загружает адресный справочник домов OpenStreetMap через Overpass и сопоставляет улицу и полный номер дома. Кэш справочника находится в `map_buildings`, прогресс — в `map_imports`. После перезапуска незавершённая подготовка продолжается; новые объявления без координат используют этот же локальный справочник. Запросы к внешнему сервису не выполняются отдельно для каждой квартиры или при каждом изменении фильтров. Публичный Overpass предназначен для умеренной нагрузки; для публичного сервиса или большого числа городов настройте свой сервер через `MAP_OVERPASS_URL`. Запрос ограничен по времени и размеру, автоматического циклического повтора при ошибке нет.

Полнота OpenStreetMap различается по городам: отсутствующие дома, неоднозначные совпадения, участки и адреса стройки не размещаются в предположительной точке. «Без координат» открывает список таких адресов: выберите «Указать на карте», нажмите на дом и подтвердите «Сохранить точку». Ручная точка сохраняется при последующих сборах. Список без координат также учитывает фильтры. Состояние подготовки и фактическое покрытие видны над картой.

Карта работает на Leaflet 1.9.4; подложка и адресные данные — [OpenStreetMap, ODbL](https://www.openstreetmap.org/copyright). Адресный справочник по умолчанию загружается с публичного Overpass VK Maps (`maps.mail.ru`); источник заменяется через `MAP_OVERPASS_URL`. Показывается атрибуция; тайлы загружаются только для текущего вида карты и кэшируются браузером, согласно [правилам использования тайлов](https://operations.osmfoundation.org/policies/tiles/). Подложка требует интернета; сохранённые координаты остаются в PostgreSQL. `MAP_TILE_URL` позволяет заменить источник тайлов. Ключи API, регистрация и платная подписка не нужны.

## Как сохраняется история

Например, при проверках с ценами `7 800 000 → 7 800 000 → 7 600 000 → 7 800 000` в истории будут три записи: начальная цена, снижение, возврат к первоначальной цене. Одинаковая цена при повторной проверке не создаёт запись. Время последней успешной проверки обновляется при каждом сборе. Существующие записи истории не перезаписываются.

Текущая цена вычисляется из последнего наблюдения и не дублируется в таблице объявлений. Обновление объявления и добавление цены выполняются одной транзакцией. Блокировка PostgreSQL сериализует сохранение одного ID, а уникальный индекс и блокировка обработчика предотвращают параллельный запуск нескольких обходов.

**Дата наблюдения** — момент, когда сборщик увидел цену; это не точное время её изменения продавцом. Если цена несколько раз менялась между запусками, промежуточные значения неизвестны. **Дата обновления Авито** заполняется только при наличии явного `dateModified` или отметки «Обновлено»; дата публикации вместо неё не используется. Все абсолютные даты хранятся с часовым поясом и отображаются по Иркутску. Человекочитаемые даты без смещения интерпретируются в часовом поясе Иркутска, ISO-даты без смещения — Москвы; при изменении формата источника это правило следует проверить.

## Сбор и ограничения доступа

Источник: `https://www.avito.ru/irkutsk/kvartiry/prodam`. Сборщик последовательно проходит страницы каталога и карточки в Иркутске, извлекает параметры из HTML и JSON-LD. По умолчанию лимита страниц и объявлений нет. Между открытиями страниц есть пауза 5 секунд. Отсутствующие необязательные поля сохраняются как NULL; неизвестные тип, адрес, площадь или цена приводят к явному пропуску карточки с сообщением о причине. Свободная планировка распознаётся по полю комнат, отдельному полю планировки или заголовку: число комнат допускается пустым, признак планировки хранится отдельно, а таблица показывает «Свободная планировка». Студия остаётся отдельным вариантом. Если число комнат неизвестно и свободная планировка явно не обозначена, карточка пропускается с сообщением о причине.

В браузерном режиме страница загружается и выполняет JavaScript в браузере пользователя. CAPTCHA пользователь проходит сам; сборщик только ожидает появления каталога или объявления, сохраняя связь с сервером. В дополнительном HTTP-режиме JavaScript не исполняется: сборщик обрабатывает обычные HTTP-перенаправления и перенаправления внутри JSON `loaderData.data` в потоковом HTML, сохраняя cookies в одном клиенте. Для последующих страниц сохраняются полученный адрес каталога и его фильтры.

Тесты на синтетических примерах разметки с хешированными CSS-классами проверяют разбор адреса, названия ЖК, цены и характеристик, запись объявления и историю цен. Полный живой обход разработчиком не проверялся: встроенный браузер среды разработки запретил открытие Авито своей политикой безопасности. При проверках HTTP-режима 15.10.2026 Авито отвечал 429 и 439. В браузерном режиме программа ждёт ручного открытия страницы до 5 минут; после таймаута сбор получает статус «Доступ Авито ограничен». В HTTP-режиме ответы 401/403/429/439 или страница проверки останавливают сбор сразу. При сетевых ошибках уже записанные объявления и история остаются доступны. Код 439 сам по себе не доказывает географическую блокировку. Локальный браузер и ручная проверка не гарантируют, что площадка разрешит автоматизированный обход.

В браузерном режиме «Продолжить сбор» использует сохранённую в PostgreSQL очередь и открывает следующую необработанную карточку. После обработки страницы продолжается переход на следующую. Адреса карточек сохраняются до их открытия; данные, цена и отметка выполнения сохраняются одной транзакцией. «Новый обход с начала» создаёт отдельный обход и повторно проверяет цены известных объявлений. Ошибки разбора сохраняются и повторяются при продолжении; снятые объявления (HTTP 404/410) пропускаются. При первом обновлении со старой версии точной очереди ещё нет: каталог просматривается с начала, а ID уже сохранённых объявлений пропускаются без открытия карточек. Это не атомарный снимок каталога: выдача может измениться в процессе обхода. Объявления, пропавшие из выдачи, не удаляются и не объявляются автоматически проданными; ориентируйтесь на «Последнюю проверку». При потере связи с локальным сборщиком более чем на 2 минуты запуск получает статус «Прерван», после чего доступно продолжение с сохранённого места. Автоматическое расписание пока не настроено.

## Прогресс и окончание обхода

Кнопка «Продолжить сбор» доступна при незавершённом обходе или оставшихся ошибках. В интерфейсе указаны номер страницы, количество уникальных карточек, очередь и ошибки. Прогресс переживает закрытие браузера, остановку компьютера и перезапуск Docker, пока сохранён том PostgreSQL. Если браузер внезапно исчез, освобождение текущего запуска занимает до двух минут.

Страницы с заголовком «Объявление не посмотреть» и сообщением «Оно ещё на проверке» или «Объявление закрыто» распознаются как модерация или закрытие объявления. Сборщик сразу передаёт её серверу без ожидания цены и адреса, пункт очереди получает состояние «Пропущено» с причиной. Ошибка разбора не учитывается; существующие данные и история цен не меняются. В текущем обходе эта карточка повторно не открывается, а новый полный обход может проверить её заново, если она появится в каталоге.

Аукционные объявления пропускаются по префиксу «Аукцион:» в заголовке либо значению «аукцион» в условиях/способе продажи. Стартовая цена не сохраняется как обычная цена квартиры, пункт очереди получает «Пропущено» с причиной без увеличения ошибок. Правило действует в браузерном и HTTP-сборе, а также при ручном импорте HTML. Существующие записи и история цен сохраняются. Проверен полный приложенный HTML; в `listing_auction.html` включён его фрагмент с заголовком и условиями продажи.

Отсутствие распознанной кнопки «Далее» не считается доказательством окончания каталога. Сборщик проверяет следующую страницу по номеру. Конец подтверждают пустая выдача, явно отключённый переход либо текущая страница в распознанной пагинации без доступных переходов вперёд. Номер страницы проверяется по самой пагинации, если он явно указан, затем по адресу; переписанный параметр URL сам по себе не приводит к остановке. При расхождении браузер ждёт обновления разметки и повторяет переход один раз. Если сброс номера повторяется, предыдущая сохранённая страница перечитывается для проверки конца каталога. Новые найденные на ней ID добавляются в очередь, прежние записи не сбрасываются. Если подтвердить конец не получилось, запуск приостанавливается с фактическим и ожидаемым номером страницы, а окно браузера остаётся открытым. Повтор набора карточек также не объявляется успешным окончанием. При загрузке каталога браузер прокручивает страницу вниз и ждёт стабилизации числа карточек до 10 секунд. Лимиты по умолчанию отключены; если их установить, они действуют на один запуск и не очищают очередь.

### Почему 30 страниц не означают весь город

В предоставленном пользователем примере общая выдача заканчивается на 30-й странице, хотя счётчик показывает 7009 объявлений. Около 50 карточек на страницу дают примерно 1500 доступных ID; повторные карточки и пропуски дополнительно уменьшают число записей. Прежняя версия ошибочно считала конец этой выдачи завершением обхода города.

Теперь браузерный сборщик делит выдачу по цене. После непустой 30-й страницы общий диапазон разделяется на 1–19 999 999 ₽ и от 20 000 000 ₽ без верхней границы. Каждый диапазон снова проходит свои страницы; если он тоже доходит до 30-й, делится дальше. Закрытые диапазоны делятся пополам, дорогой хвост расширяется. Например, после 1–10 000 000 ₽ следует 10 000 001–19 999 999 ₽: промежутков между целыми ценами нет. Изначальная цена объявления не ограничивает его участие в новых обходах.

Код фильтра проверен на двух URL, которые предоставил пользователь: 1–2 млн ₽ и от 20 млн ₽. Перед сохранением страницы проверяется сохранность фильтра в адресе браузера. Сброс фильтра останавливает запуск с сохранением прогресса. Каждый ID открывается один раз за обход города, даже если встретился в нескольких диапазонах. В интерфейсе видны текущая цена, страница, пройденные и оставшиеся диапазоны. Общее число диапазонов может расти при разделении.

При обновлении существующий завершённый обход из 30 страниц снова становится доступным для продолжения. Сохранённые объявления, очередь и история цен остаются на месте; карточки, уже имеющиеся в базе к моменту обновления, повторно не открываются. Для последующей проверки их цен используйте «Новый обход с начала».

Успешное завершение означает, что все конечные диапазоны прошли без достижения ограничения глубины. Если даже одна точная цена занимает 30 страниц, сбор получает статус «Частично завершён»: дальнейшее деление по цене невозможно, полнота не заявляется. Авито меняет выдачу во время сбора, поэтому точного совпадения с числом в счётчике в другой момент гарантировать нельзя. Новый обход ищет новые объявления и проверяет изменения цен. Эта очередь диапазонов используется в основном браузерном режиме; отдельный HTTP-режим сохраняет прежний последовательный обход.

## Настройки

Необязательно скопируйте `.env.example` в `.env` перед первым запуском:

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `WEB_PORT` | 8088 | Локальный порт интерфейса |
| `POSTGRES_PASSWORD` | avito_local_only | Пароль PostgreSQL; при спецсимволах требуется URL-кодирование в DATABASE_URL |
| `REQUEST_DELAY_SECONDS` | 5 | Базовая пауза перед запросом. В браузерном режиме перед объявлением действует половина базовой паузы (по умолчанию 2,5 секунды, минимум 1 секунда) |

| `MAX_LISTINGS` | 0 | Лимит обработанных карточек за запуск, включая ошибки и пропуски; повтор одной карточки не расходует ещё одно место; 0 — без лимита |
| `COLLECTOR_MODE` | browser | `browser` — локальный браузер; `http` — HTTP-запросы из Docker |

| `AVITO_PROXY_URL` | пусто | Адрес HTTP(S)/SOCKS5/SOCKS5h-прокси, при необходимости с логином и паролем |

Прокси используется только сборщиком и диагностической командой. При сбое прокси прямого резервного подключения нет; системные `HTTP_PROXY`, `HTTPS_PROXY`, `ALL_PROXY` и `NO_PROXY` для этого клиента не используются. Пароль хранится в `.env`, который исключён из Git, Docker-контекста и архива исходников; API его не возвращает. Настройки маскируют секреты, пользовательские сообщения об ошибках не включают реквизиты. Проверка TLS-сертификатов включена.

После изменения настроек повторите `docker compose up -d`. Интерфейс слушает только `127.0.0.1`; PostgreSQL и backend не публикуют порты на хост. Данные PostgreSQL находятся в томе `housing-scraper_postgres_data` и сохраняются после обычного `docker compose down`. Не добавляйте `-v`, если хотите сохранить базу.

## Скрипт и импорт HTML

Запустить сбор из командной строки вместо кнопки:

```sh
docker compose exec backend python -m app.collect
```

Скрипт использует ту же очередь и ту же историю. В режиме `browser` он ставит задание в очередь для запущенного локального сборщика. В режиме `http` выполняет HTTP-сбор при свободном обработчике; при блокировке или ошибке завершится с ненулевым кодом.

Для полного нового обхода используйте `python -m app.collect --new` вместо обычной команды; продолжение в браузерном режиме используется по умолчанию.

Для проверки парсера или импорта вручную сохранённой **актуальной** страницы без повторного сетевого запроса:

```sh
docker compose cp /absolute/path/listing.html backend:/tmp/listing.html
docker compose exec backend python -m app.collect --html /tmp/listing.html --url https://www.avito.ru/irkutsk/kvartiry/example_1234567890
```

Замените URL исходным адресом сохранённого объявления. Дата наблюдения при импорте — текущее время: импорт старых HTML-файлов как свежих исказит хронологию.

## Проверки

Тесты используют отдельную базу с именем, оканчивающимся на `_test`, и отказываются запускаться на рабочей базе. После сборки контейнеров:

```sh
docker compose exec db createdb -U avito avito_test
docker compose run --build --rm --no-deps backend-test
# Только тесты, которым не нужен PostgreSQL:
docker compose run --rm --no-deps backend-test pytest -q -m 'not db'
# Только интеграционные сценарии:
docker compose run --rm --no-deps backend-test pytest -q -m db
```

Проверки диапазонов включают точное воспроизведение двух пользовательских фильтров, изменение длины кодированной цены, непрерывность границ, дорогой хвост, повторное деление, общий учёт лимитов, продолжение посреди диапазона, отсутствие повторных открытий и ложного завершения при одной цене. Проверки очереди включают продолжение посреди страницы с новым токеном браузера, переход на следующую страницу, отсутствие и повтор пагинации, перенос старых объявлений, повтор ошибок, немедленный пропуск приложенных примеров модерации и закрытого объявления с HTTP 200/404/410, продолжение после него, сохранение старой истории цен, остановку по лимиту и атомарный откат записи цены вместе с очередью.

Создание тестовой базы требуется один раз. Если настроен другой пароль, замените его в тестовом URL. Проверяются поля, вторичка/новостройка, студия, свободная планировка без числа комнат, сохранение и обновление планировки через API и базу, отсутствие даты обновления, JSON-LD, пагинация, HTTP-перенаправления и перенаправления внутри HTML с кодом 200, сохранение фильтров каталога, запрет внешних и циклических перенаправлений, смена URL при правильном текущем номере страницы, одноразовый повтор перехода и перепроверка последней страницы без сброса очереди, ошибки разметки, ограничения доступа, история изменения и возврата цены, независимость разных ID, откат транзакции, запрет параллельного запуска, API таблицы и истории. Также проверяются реальный HTTP CONNECT к локальному тестовому прокси, передача авторизации, отсутствие прямого резервного подключения, обязательный прокси, завершение задания при ошибке настроек, сокрытие пароля и проверка страны выхода. Тесты изолируют пользовательские настройки прокси и не обращаются к внешним сайтам. Примеры находятся только в `backend/tests/fixtures`; в рабочую базу они не загружаются. Образец перенаправления минимально воспроизводит реальный ответ Авито. Синтетические примеры `listing_hashed_layout.html` и `listing_2026_11.html` воспроизводят структуру блока адреса `#item-view-address`, параметров и названия новостройки. Файл `listing_closed.html` содержит фрагмент другого предоставленного пользователем HTML с сообщением «Объявление закрыто»; полный HTML также проверен парсером без сетевых запросов.

Проверки масштаба графиков: `npm test` в `frontend` (встроенный тестовый модуль Node.js, без дополнительных зависимостей). Они проверяют непрерывность, монотонность, сохранение крайних значений, выбор линейного/нелинейного режима, плотность делений, пустые и постоянные выборки.

Проверки CI разделены на тесты Python без PostgreSQL, интеграционные тесты и сборку интерфейса. В рабочем образе backend pytest не установлен.

Сборка интерфейса: `npm ci && npm run build` в `frontend` (Node.js 22.12+). Журналы: `docker compose logs backend`. Остановка с сохранением данных: `docker compose down`.

Схема и принципы нормализации описаны в [SCHEMA.md](SCHEMA.md). Изменения структуры управляются Alembic; при старте backend миграции применяются автоматически.

Параметр `sort_by`: `rooms`, `total_area`, `kitchen_area`, `living_area`, `floor`, `ceiling_height`, `finish`, `price`, `price_per_sqm`, `last_seen_at` (по умолчанию). Параметр `sort_order`: `asc` или `desc` (по умолчанию). Неподдерживаемые значения возвращают HTTP 422.

Параметры фильтрации `GET /api/listings`:

- `market_type`: `all`, `secondary`, `new`.
- Повторяемые `rooms`: целое число комнат (0 — студия) или `open_plan`; `complex_id`: ID ЖК, 0 — без ЖК.
- Пары `_min` / `_max` для `total_area`, `floor`, `floors_total`, `ceiling_height`, `price`, `price_per_sqm`, `construction_year` (границы включительно).
- `balcony`: `all`, `present`, `balcony`, `loggia`, `absent`, `unknown`.
- Повторяемый `bathroom`: `combined`, `separate`; повторяемый `finish`: значение отделки из справочника.
- Повторяемые `house_type`, `passenger_elevator`, `parking`: значения соответствующих справочников. Несколько выбранных значений внутри одного фильтра объединяются через «или», разные фильтры — через «и».

«Настроить поля» над таблицей позволяет выбрать видимые столбцы; выбор сохраняется в браузере и действует для всех городов. «Показать все» возвращает полный набор. Как минимум один столбец остаётся видимым.

Тип дома, пассажирский лифт и варианты парковки хранятся в нормализованных справочниках характеристик. Количество пассажирских лифтов сохраняется, если оно указано; «есть» не превращается в выдуманное количество, «нет» отличается от отсутствующих сведений. Год постройки — отдельное целое поле; срок сдачи новостройки его не заменяет. Миграция 008 добавляет поля без изменения объявлений и истории цен; старые записи заполняются при повторном обходе.

`GET /api/listings/filter-options` возвращает все представленные ЖК, варианты комнат и отделки без неиспользуемых записей справочников. Ответ таблицы содержит `total` (после фильтров), `total_all` (вся база), `price_per_sqm` и `complex_id` в каждой строке. Некорректные диапазоны возвращают HTTP 422.

`GET /api/analytics` принимает те же параметры фильтрации, что и таблица. Возвращает `total`, `priced_count`, `calculated_at`, `metrics` для `price`, `price_per_sqm`, `total_area` и `points`. Каждый показатель содержит `count`, `mean`, `median`, массив `modes` и `mode_frequency`. При пустой выборке среднее/медиана равны `null`, массив мод пуст. Расчёты и точки формируются из одного снимка базы; запрос не меняет объявления и историю цен.

Для выборки `POST /api/runs`: `{"mode":"new","city_id":1,"collection_mode":"sample"}`; для продолжения — `mode:"resume"` с тем же городом и режимом. Параметр `city_id` в таблице, аналитике, вариантах фильтров, прогрессе и последнем запуске ограничивает данные выбранным городом. Без него сохраняется совместимость прежнего API.


## Сброс пагинации на первую страницу

При полном обходе Авито может вернуть страницу 1 вместо запрошенной, даже до прежнего предела в 30 страниц. Локальный сборщик сначала повторяет переход и перепроверяет предыдущую страницу. Если сброс сохраняется, сервер проверяет фактически полученную страницу, город, рынок, цену и радиус, затем делит текущий ценовой диапазон пополам и продолжает с его дочерних диапазонов. Родительский диапазон не объявляется полностью пройденным; сохранённые объявления и цены остаются на месте, уже обработанные ID повторно не открываются. Состояние деления сохраняется в существующей очереди PostgreSQL.

Неизвестная разметка, CAPTCHA или сброс фильтров не разрешают такое восстановление. Диапазон из одной цены отмечается как ограниченный, а остальные диапазоны продолжают обрабатываться; итог остаётся частичным. Ценовые группы выборки 1000 не делятся этим механизмом. Для автоматического восстановления нужен перезапуск «Запустить сборщик.command» (протокол 6); новый обход с начала запускать не требуется.

Кодирование фильтра использует алфавит Авито: `_` вместо `+`, `~` вместо `/`. Это существенно при восьмизначных границах цены вместе с радиусом: стандартный вариант с `-` сайт может отбросить. Старые сохранённые ссылки читаются и перед открытием переводятся в формат Авито. При временном исчезновении фильтров сборщик ждёт стабилизации страницы и один раз повторно открывает исходный каталог. Если цена или радиус не восстановились, неотфильтрованная страница в очередь не попадает; сообщение показывает ожидаемые и фактически прочитанные ограничения.

Дополнительные параметры аналитики: `budget_min`, `budget_max`, `compare_by` (`rooms`, `district`, `complex`, `area`, `finish`, `building_age`, `building_type`, `market_type`, `offer`). Ответ расширен полями `distributions`, `budget`, `comparison`, `quality`; исходные `metrics` и `points` сохранены. Общие повторяемые фильтры: `sale_scope`, `premise_kind`, `construction_status`, `district` (значение `__unknown__` — район не указан).
