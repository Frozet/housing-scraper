# Необязательное подключение собственного прокси

По умолчанию приложение использует бесплатный локальный браузер. Регистрироваться в сторонних сервисах, покупать прокси или оплачивать подписку для запуска программы не требуется. Этот раздел нужен только при наличии собственного прокси и выборе дополнительного режима `COLLECTOR_MODE=http`. HTTP-сборщик поддерживает HTTP CONNECT, HTTPS-прокси, SOCKS5 и SOCKS5h. Параметры задаются в `.env` в корне проекта. После их изменения контейнер backend нужно пересоздать. На отдельный локальный браузер эти настройки прокси не распространяются.

Прокси не гарантирует отсутствие блокировок Авито. ID объявлений и история цен остаются прежними при смене сетевого маршрута.

## Работа без прокси

Оставьте в `.env` следующие значения:

```dotenv
AVITO_PROXY_URL=
AVITO_PROXY_REQUIRED=false
```

Прямой доступ зависит от текущего интернет-соединения и ответа Авито. HTTP 429/439 не доказывают конкретную причину отказа. Импорт ранее сохранённого вами HTML объявления также доступен без сетевого подключения к Авито; порядок описан в README.

## Настройка

1. Для уже имеющегося собственного прокси нужны адрес сервера, соответствующий HTTP- или SOCKS5-порт и, при наличии авторизации, логин и пароль. Программа выполняет запросы последовательно.
2. Если `.env` ещё нет, скопируйте `.env.example` в `.env`. Запишите реальные параметры только в `.env`:

```dotenv
AVITO_PROXY_URL='http://USER:PASSWORD@HOST:PORT'
AVITO_PROXY_REQUIRED=true
COLLECTOR_MODE=http
```

Для SOCKS5 используйте `socks5h://USER:PASSWORD@HOST:PORT` с SOCKS5-портом провайдера. Порты HTTP и SOCKS5 могут различаться. Строки выше — примеры, а не рабочие реквизиты. Спецсимволы логина и пароля (`@`, `:`, `#`, `/`, `%` и др.) должны быть URL-кодированы; одинарные кавычки защищают значение от подстановок в `.env`.

Авито использует HTTPS, однако для стандартного CONNECT-прокси адрес обычно начинается с `http://`: это протокол соединения с самим прокси. `https://` ставьте только если провайдер поддерживает TLS-соединение к прокси. Проверка сертификата самого Авито остаётся включённой.

3. Из каталога проекта примените настройки:

```sh
docker compose up -d --no-build --force-recreate backend frontend
```

При запуске проекта впервые сначала соберите контейнеры командой `docker compose up -d --build`.

4. Проверьте настроенный маршрут:

```sh
docker compose exec backend python -m app.check_proxy
```

Команда через **тот же прокси** запрашивает у [country.is](https://country.is/) выходной IP и страну. При `RU` она загружает первую страницу каталога Авито и проверяет наличие карточек. Это диагностический запуск: объявления в базу не записываются. В ответе показываются `exit_ip`, `country`, `listings_found` и сообщение; адрес прокси, логин и пароль не выводятся. При ошибке команда завершается с кодом 1.

Страна определяется по GeoIP, возможны неточности базы. Значение не `RU` требует сверки с выбранной локацией у провайдера. Недоступность country.is также может помешать диагностике; регулярный сбор не зависит от этого сервиса.

После успешной проверки нажмите **«Запустить сбор»** в [интерфейсе](http://localhost:8088).

## Ошибки

| Сообщение | Что проверить |
|---|---|
| «Прокси не настроен» | В `.env` заполнен `AVITO_PROXY_URL`, контейнер пересоздан |
| «Некорректный адрес прокси» | Указаны протокол, хост и порт; логин и пароль заданы вместе и URL-кодированы |
| «Ошибка подключения или авторизации прокси» / 407 | Реквизиты, срок аренды, правильный порт и разрешённый способ авторизации |
| «Не удалось определить внешний IP» | Доступность прокси и country.is |
| «Авито ограничил доступ» / 429 / 439 | Российский маршрут не обеспечил доступ; сам код не устанавливает причину ограничения |

При недоступности выбранного прокси сборщик не переключается на прямой доступ и не меняет IP автоматически. HTTP_PROXY/HTTPS_PROXY/ALL_PROXY/NO_PROXY из среды не подменяют явно выбранный маршрут. Сохранённая база и история цен остаются доступны при сетевых ошибках.

При запуске Python без Docker установите обе группы зависимостей: `pip install -r requirements.txt -r requirements-proxy.txt` из `backend`. SOCKS5 требует `socksio`; в Docker он уже установлен.
